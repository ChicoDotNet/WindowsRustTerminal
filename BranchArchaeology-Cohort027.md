# Branch Archaeology — Cohort 027

This cohort closes the original 2019 ConPTY passthrough proof of concept after tracing its intent through the modern passthrough architecture.

## `dev/migrie/f/passthrough-2019`

- Tip `491ec14291357ae93af6376ff54df530d34f847b`, dated 2019-07-19, adds input passthrough on top of the earlier basic passthrough implementation.
- Functional commit `f5939ebd61682bec9bdec56fdcdf5545171441bb` introduced a custom `ENABLE_PASSTHROUGH_MODE`, bypassed normal output handling through `VtIo`/the VT renderer, and explicitly recorded three structural problems: entering passthrough did not immediately stop an active frame, exiting left rendering state torn, and the mode flag was probably placed in the wrong layer.
- Tip commit added input passthrough by bypassing the input state machine and directly writing character `KeyEvent`s when passthrough was active.
- This implementation was a useful proof that raw VT could cross ConPTY, but its mode/renderer architecture did not survive.
- Definitive output successor: PR #17510, `A minor ConPTY refactoring: Goodbye VtEngine Edition`, merged as `450eec48de252a3a8d270bade847755ecbeb5a75`. It removes the old asynchronous `VtEngine` translation model, translates Console API calls synchronously, and passes VT output generated by applications to the hosting terminal unmodified. It closes #1173 among other passthrough issues.
- Definitive input successor: PR #17741, `ConPTY: Flush unhandled sequences to the buffer`, merged as `6dd9c468ebc77e0025939b32fb927e85f3172b25`. It gives the input parser an explicit pass-through path for sequences it does not consume, fixing responses that would otherwise be swallowed.
- Disposition: **NO-PORT / architectural proof superseded by #17510 + #17741**.
- Recovery value: preserve the negative knowledge from 2019 — passthrough should not be modeled as a renderer flag whose transitions can tear frame state, and input should not be reduced to synthetic character-only `KeyEvent`s.
- Branch retirement: **SAFE after this ledger commit**.
